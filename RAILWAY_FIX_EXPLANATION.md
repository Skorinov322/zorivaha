# 🔧 Объяснение исправления Railway деплоя

## Проблема:

При деплое на Railway возникала ошибка:
```
django.db.utils.OperationalError: could not translate host name "postgres.railway.internal" to address: Name or service not known
```

## Причина:

Миграции базы данных выполнялись в `build.sh` **во время сборки Docker образа**.

На этапе сборки:
- ❌ База данных PostgreSQL **недоступна**
- ❌ Переменная `DATABASE_URL` может быть недоступна
- ❌ Сетевое подключение к `postgres.railway.internal` не работает

База данных доступна только **во время выполнения** (runtime), когда контейнер уже запущен.

## Решение:

### 1. Разделили процесс на два этапа:

#### Build Time (сборка образа) - `build.sh`:
```bash
✅ Установка зависимостей (pip install)
✅ Сборка статических файлов (collectstatic)
❌ НЕ выполняем миграции БД
```

#### Runtime (запуск приложения) - `railway_start.sh`:
```bash
✅ Выполнение миграций БД (migrate)
✅ Создание таблицы кеша (createcachetable)
✅ Запуск Gunicorn сервера
```

### 2. Обновили `railway.toml`:

**Было:**
```toml
startCommand = "gunicorn config.wsgi --bind 0.0.0.0:$PORT --workers 2 --timeout 120"
```

**Стало:**
```toml
startCommand = "bash railway_start.sh"
```

## Почему это работает:

1. **Build time**: Собирается образ без подключения к БД
2. **Deploy time**: Railway запускает контейнер
3. **Runtime**: 
   - База данных уже доступна
   - Выполняются миграции
   - Создается таблица кеша
   - Запускается веб-сервер
   - Healthcheck проходит успешно ✅

## Аналогия:

Это как пытаться позвонить другу **до того**, как у вас появился телефон:
- ❌ **Build time**: У вас еще нет телефона (нет подключения к БД)
- ✅ **Runtime**: Телефон уже есть, можно звонить (БД доступна)

## Файлы изменены:

1. `build.sh` - убраны миграции
2. `railway_start.sh` - **новый файл** с миграциями и запуском
3. `railway.toml` - обновлена команда запуска
4. Документация обновлена

## Результат:

✅ Сборка проходит успешно  
✅ Миграции выполняются при запуске  
✅ Healthcheck работает  
✅ Приложение запускается  

---

**Важно:** Это стандартная практика для Railway и других PaaS платформ - миграции всегда выполняются в runtime, а не в build time.
