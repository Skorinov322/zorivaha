# FAQ: Миграция и оптимизация БД

## 🤔 Общие вопросы

### Зачем нужна оптимизация БД?
**Ответ:** Текущая структура имеет дублирование (RoomReview vs Review) и избыточные модели (PageView, BookingFunnel), которые не используются. Оптимизация упростит поддержку и улучшит производительность.

### Почему мягкая оптимизация, а не радикальная?
**Ответ:** Мягкая оптимизация безопаснее:
- Нет риска потери данных
- Можно откатить на любом этапе
- Команда имеет время на адаптацию
- Постепенное внедрение изменений

### Сколько времени займет миграция?
**Ответ:** 
- Подготовка: 1-2 часа
- Миграция данных: 30 минут - 2 часа (зависит от объема)
- Обновление кода: 2-4 часа
- Полный цикл: 6-12 месяцев (постепенно)

## 🔧 Технические вопросы

### Что делать, если миграция отзывов упала с ошибкой?
**Ответ:**
1. Не паникуйте - транзакция откатится автоматически
2. Проверьте ошибку в выводе
3. Исправьте проблему (обычно это отсутствующие связи)
4. Запустите снова с `--dry-run`
5. Если не помогает - восстановите из резервной копии

```bash
# Откат из резервной копии
cp db.sqlite3.backup_20240101 db.sqlite3
```

### Как проверить, что миграция прошла успешно?
**Ответ:**
1. Проверьте количество записей:
```python
from apps.hotel.models import RoomReview
from apps.reviews.models import Review
print(f"Старых: {RoomReview.objects.count()}")
print(f"Новых: {Review.objects.count()}")
```

2. Проверьте несколько отзывов в админке
3. Убедитесь, что связи с бронированиями сохранились
4. Проверьте, что оценки корректны

### Можно ли запустить миграцию несколько раз?
**Ответ:** Да, скрипт пропустит уже мигрированные отзывы. Безопасно запускать повторно.

### Что делать, если в production уже есть данные?
**Ответ:**
1. Сначала протестируйте на копии production БД
2. Создайте резервную копию production
3. Запланируйте миграцию в нерабочее время
4. Запустите миграцию
5. Проверьте результат
6. Мониторьте систему после миграции

## 📊 Вопросы о данных

### Потеряются ли данные при миграции?
**Ответ:** Нет, если следовать инструкциям:
- Скрипты используют транзакции (откат при ошибке)
- Старые данные не удаляются автоматически
- Всегда делайте резервную копию перед миграцией

### Что делать со старыми данными после миграции?
**Ответ:** 
1. Оставьте на 1-2 месяца для проверки
2. Убедитесь, что новые данные корректны
3. Удалите старые данные:
```python
from apps.hotel.models import RoomReview
RoomReview.objects.all().delete()
```

### Можно ли откатить миграцию?
**Ответ:** Да, несколькими способами:
1. Восстановить из резервной копии (самый надежный)
2. Удалить мигрированные записи вручную
3. Использовать git для отката кода

## 🚀 Вопросы о процессе

### С чего начать?
**Ответ:**
1. Прочитайте `QUICK_START_MIGRATION.md`
2. Запустите `python manage.py check_deprecated_usage`
3. Создайте резервную копию БД
4. Запустите миграцию с `--dry-run`

### Нужно ли останавливать сервер для миграции?
**Ответ:** 
- **Для dev/staging:** Не обязательно
- **Для production:** Рекомендуется (или запланируйте в нерабочее время)

### Как часто нужно проверять прогресс?
**Ответ:**
- Первый месяц: еженедельно
- 2-6 месяцев: ежемесячно
- После 6 месяцев: по необходимости

```bash
python manage.py check_deprecated_usage
```

## 💻 Вопросы о коде

### Как найти все использования deprecated моделей в коде?
**Ответ:**
```bash
# Через скрипт
python scripts/migrations/check_deprecated_usage.py

# Через grep
grep -r "RoomReview" apps/
grep -r "PageView" apps/
grep -r "from apps.crm.models import Task" apps/

# Через IDE (VS Code, PyCharm)
# Ctrl+Shift+F → поиск по всем файлам
```

### Нужно ли обновлять тесты?
**Ответ:** Да, если тесты используют deprecated модели:
```python
# ❌ Старый тест
from apps.hotel.models import RoomReview
review = RoomReview.objects.create(...)

# ✅ Новый тест
from apps.reviews.models import Review
review = Review.objects.create(...)
```

### Что делать с импортами в старом коде?
**Ответ:** Заменить на новые:
```python
# ❌ Deprecated
from apps.hotel.models import RoomReview
from apps.crm.models import Interaction, Task, Message

# ✅ Новые
from apps.reviews.models import Review
from apps.bookings.models import BookingHistory
from apps.crm.models import AdminComment
from apps.notifications.models import ContactMessage
```

## 🔐 Вопросы о безопасности

### Безопасно ли запускать скрипты в production?

- Создали резервную копию
- Запланировали в нерабочее время

**Ответ:**
1. Не паникуйте
2. Остановите процесс (Ctrl+C)
3. Восстановите из резервной копии
4. Проверьте логи ошибок
5. Исправьте проблему
6. Попробуйте снова на копии БД

### Как защититься от потери данных?
**Ответ:**
1. **Всегда** делайте резервную копию
2. Используйте `--dry-run` для тестирования
3. Тестируйте на копии production
4. Мониторьте процесс миграции
5. Проверяйте результаты после миграции

## 📈 Вопросы о производительности

### Повлияет ли миграция на производительность?
**Ответ:** 
- **Во время миграции:** Возможна небольшая нагрузка на БД
- **После миграции:** Производительность улучшится (меньше таблиц)

### Сколько времени займет миграция больших объемов?
**Ответ:** Примерно:
- 100 отзывов: ~10 секунд
- 1000 отзывов: ~1 минута
- 10000 отзывов: ~10 минут

Используйте `--dry-run` для оценки времени.

### Можно ли ускорить миграцию?
**Ответ:** Да:
1. Запускайте в нерабочее время (меньше нагрузка)
2. Отключите ненужные middleware
3. Используйте `bulk_create` (уже используется в скриптах)

## 🎯 Вопросы о результатах

### Как измерить успех миграции?
**Ответ:** Проверьте:
- [ ] 0 записей в deprecated таблицах
- [ ] 0 использований в коде
- [ ] Все тесты проходят
- [ ] Нет ошибок в production
- [ ] Команда довольна

### Что делать после успешной миграции?
**Ответ:**
1. Мониторьте систему 1-2 недели
2. Соберите обратную связь от команды
3. Обновите документацию
4. Запланируйте удаление deprecated моделей (через 6-12 месяцев)

### Когда можно удалить deprecated модели?
**Ответ:** Через 6-12 месяцев после миграции, когда:
- Нет данных в deprecated таблицах
- Нет использований в коде
- Команда привыкла к новым моделям
- Нет жалоб от пользователей

## 🎓 Вопросы для новичков

### Я новый разработчик, что мне нужно знать?
**Ответ:**
1. Прочитайте `docs/DEPRECATION_PLAN.md`
2. Не используйте deprecated модели (помечены ⚠️)
3. Используйте альтернативы (см. таблицу в документации)
4. Спрашивайте, если не уверены

### Какие модели можно использовать?
**Ответ:** Все, кроме помеченных ⚠️ DEPRECATED:
- ✅ `reviews.Review` (не `hotel.RoomReview`)
- ✅ `notifications.ContactMessage` (не `crm.Message`)
- ✅ `BookingHistory` + `AdminComment` (не `crm.Interaction`)
- ✅ `DailyMetrics` (не `PageView`, `BookingFunnel`)
